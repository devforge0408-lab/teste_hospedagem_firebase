Como hospedar um site no Firebase App Hosting

O Firebase App Hosting é a solução do Google para hospedar apps web full-stack (Next.js, Angular e backends Node). O fluxo recomendado é 100% pelo Firebase Console integrado ao GitHub — sem precisar instalar CLI nenhuma. É exatamente assim que esta landing page foi para o ar.

  1. 1. Suba seu código para o GitHub

    Crie um repositório no GitHub e faça push do seu app. É o repositório que o Firebase vai observar — cada commit pode virar um deploy.

    git init
git add -A
git commit -m "meu site"
git remote add origin https://github.com/SEU-USUARIO/SEU-REPO.git
git push -u origin main

  2. 2. Crie um projeto no Firebase Console

    Acesse o Firebase Console, clique em "Adicionar projeto" e crie um projeto. Certifique-se de que ele esteja no plano Blaze (pague apenas pelo que usar — necessário porque o App Hosting usa Cloud Run e Cloud Build).

  3. 3. Abra o App Hosting

    No menu lateral do console, vá em Build > Hosting & Serverless > App Hosting e clique em "Get started" (Começar).

  4. 4. Conecte o GitHub

    O assistente usa o Developer Connect do Google Cloud: ele pede para instalar e autorizar o app do Firebase no GitHub na sua conta/organização. Autorize o acesso e selecione o repositório do seu site. Nenhum comando de terminal é necessário.

  5. 5. Configure o backend

    Ainda no assistente, defina:

    • Região primária — ex.: us-central1, europe-west4 ou asia-east1;
    • Diretório raiz do app — deixe / se o código está na raiz do repo;
    • Live branch — o branch que vai para produção (ex.: main);
    • Rollouts automáticos — deixe ativado para deploy a cada push;
    • Nome do backend e o runtime Node.js (o mais recente já vem pré-selecionado).

  6. 6. "Finish and deploy"

    Crie um Firebase web app quando solicitado e clique em Finish and deploy. O App Hosting gera uma URL gratuita no formato backend-id--project-id.us-central1.hosted.app já com HTTPS.

  7. 7. Deploy contínuo via push

    Pronto! A cada git push no live branch, o Developer Connect dispara um evento, o Cloud Build faz o build, o Cloud Run sobe a nova versão e o Cloud CDN serve o conteúdo. Você acompanha o status do rollout pelo console do Firebase ou direto no commit do GitHub (via checks API).

  8. 8. (Opcional) Domínio personalizado

    Na aba de domínios do App Hosting, adicione seu domínio e configure os registros DNS indicados. O certificado SSL é provisionado automaticamente.

💡 Dica: garanta que seu package.json tenha o script "start" e que o servidor escute em process.env.PORT — é assim que o App Hosting sabe como rodar seu app. Para customizações avançadas, você pode adicionar um apphosting.yaml na raiz do repositório.

📎 Nota: existe a opção de deploy via Firebase CLI ou upload de zip direto pelo console, mas o fluxo recomendado — e o que ensinamos no canal — é a integração contínua com o GitHub.
